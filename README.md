# MS-Factory — نظام محاسبة أونلاين للموبايل

نظام محاسبي مستقل مبني من الصفر بوظائف شبيهة بـ Manager.io — **مش** تفكيك
للكود الأصلي ولا نسخ لتصميمه. يعمل كتطبيق ويب تقدّمي (PWA) على الموبايل،
بواجهة عربية RTL.

> للحصول على خطة التطوير الكاملة (الاستضافة، الموديولات، بوابة العميل) راجع
> [`PLAN.md`](PLAN.md).

## المزايا

- **محاسبة القيد المزدوج** — كل مستند يتحول لقيد متوازن تلقائياً، والقيود
  غير المتوازنة مرفوضة عند نقطة واحدة.
- **متعدد الشركات (multi-tenant)** — كل شركة معزولة تماماً، وكل استعلام
  مفلتر بـ `company_id`.
- **أدوار وفريق** — مالك / مدير / محاسب / مبيعات / مشاهد.
- **دليل حسابات** جاهز (أصول/التزامات/ملكية/إيرادات/مصروفات) قابل للتوسيع.
- **عملاء وموردون** مع كشف حساب ورصيد لحظي.
- **فواتير بيع وشراء** ببنود متعددة وضريبة.
- **مدفوعات** (تحصيل/دفع) مع توزيع تلقائي على أقدم الفواتير.
- **قيود يدوية** مع تحقق من توازن المدين والدائن.
- **إعدادات الشركة والضرائب** — الضرائب **بيانات مش كود**، فتشتغل لأي دولة.
- **تقارير**: قائمة الدخل، الميزانية العمومية، ميزان المراجعة، أعمار الديون،
  دفتر اليومية.
- **PWA**: يُثبَّت على الموبايل، وواجهة عربية RTL، ويعمل بدون إنترنت للواجهة.

## التشغيل

```bash
pip install -r requirements.txt
python -m uvicorn app.main:app --host 0.0.0.0 --port 12000
```

افتح `http://localhost:12000`.

لتهيئة قاعدة البيانات والبيانات التجريبية:

```bash
python -m alembic upgrade head
python -m app.seed
```

الدخول التجريبي: **admin@msfactory.eg / Admin123!@#**

> `uvicorn` مش على PATH — استخدم `python -m uvicorn` دايماً.

## الإعدادات (متغيرات البيئة)

كل الإعدادات لها قيم افتراضية للتطوير، وتُضبط في الإنتاج ببادئة `MSFACTORY_`:

| المتغير | الوصف |
|---|---|
| `MSFACTORY_ENVIRONMENT` | `production` لتشغيل ضوابط الإنتاج |
| `MSFACTORY_SECRET_KEY` | مفتاح سري قوي (٣٢ حرف على الأقل في الإنتاج) |
| `MSFACTORY_DATABASE_URL` | رابط قاعدة البيانات (PostgreSQL) |
| `MSFACTORY_REDIS_URL` | Redis لتحديد معدل الطلبات (اختياري — يفشل بأمان) |
| `MSFACTORY_CORS_ORIGINS` | الأصول المسموحة، مفصولة بفواصل |

## الاختبارات

```bash
MSFACTORY_LOGIN_RATE_LIMIT_PER_MINUTE=1000 \
MSFACTORY_RATE_LIMIT_PER_MINUTE=5000 \
python -m pytest
```

> نرفع حد الطلبات أثناء الاختبار وإلا فإن محدّد الدخول يوقفها.
> تنبيه: تشغيل الاختبارات يعطّل حساب الديمو — أعد `python -m app.seed` بعده.

## النشر بـ Docker

```bash
docker compose up --build
```

`docker-compose.yml` يشغّل التطبيق + PostgreSQL 17 + Redis، و`Dockerfile`
مبني على `python:3.13-slim` ويعمل بمستخدم غير مميز.

## النسخ الاحتياطي

```bash
./scripts/backup.sh [output-dir]
```

يأخذ نسخة مضغوطة ويحتفظ بآخر ٣٠ نسخة. يُجدول على cron في الإنتاج.

## البنية

```
app/
  api/v1/          نقاط الـ API (auth, accounts, contacts, invoices, payments,
                   journal, reports, settings)
  core/            الإعدادات، الأمان، الصلاحيات، تحديد المعدل، Redis
  db/models/       الجداول: identity, accounting, operations
  domain/          قواعد المحاسبة (القيد المزدوج، القيود، الضريبة)
  repositories/    طبقة الوصول للبيانات
  services/        منطق العمل (auth, invoices, payments, settings, onboarding)
  workers/         المهام الخلفية
  main.py          تجميع التطبيق + خدمة الواجهة الثابتة
static/            واجهة الموبايل (HTML/CSS/JS بدون build)
alembic/           ترحيلات قاعدة البيانات
tests/             اختبارات الـ API والمحاسبة
```

## مبادئ التصميم

- **الأرصدة لا تُخزَّن** — كل التقارير تُجمّع من صفوف `JournalLine`، فلا يمكن
  أن تتعارض التقارير مع الدفاتر.
- **نقطة تحكّم واحدة** — كل مستند يمر عبر قيد متوازن في طبقة المحاسبة.
- **العزل بالشركة** — كل استعلام مفلتر بـ `company_id`.
- **الضرائب بيانات** — أكواد الضريبة صفوف في قاعدة البيانات، لا أرقام مثبتة.
